通铺平台场景图工作流

案例与工作流说明 · 配套源码保存在 GitHub 私人仓库。以下是已有规则与作品的整理，不是新批次的实测报告。

查看 GitHub 项目、Skill 与案例归档 ↗（需授权）

工作流定位

从一款商品的多场景，到多款商品的场景任务。

减少反复编写提示词与换场景后的商品漂移，让不同平台的图像要求进入同一份任务清单。

我的贡献

将项目中的设计判断沉淀为 Skill 规则，组织产品资料、任务清单与参考案例；建立检查标准，在关键节点审核并把控最终视觉质量。具体项目的职责范围以对应执行记录为准。

输入与交付

输入：商品实拍、SKU、真实用途、平台与场景方向。

交付：场景方案、逐图提示词、成图及检查记录。

批量组织：以 SKU × 场景 × 平台组织任务，逐项核对产品与人物互动。

这里的批量指按清单组织多项任务，不等同于模型一次出完整套图、无限并发或全程无需人工。

执行流程

1. 识别产品、平台与真实使用方式，登记缺失信息。
2. 拆分人物互动、静物、环境等场景任务，不用同一房间替代所有情境。
3. 把商品不变量、平台限制、光线与场景要求写入逐图提示词。
4. 按清单分批执行，查看每张结果；产品结构或用途错误先修正。
5. 按 SKU 与场景命名交付，保留提示词、结果和未通过项。

质量控制与人工节点

核对商品比例、组件数量、连接结构、人物动作与平台限制。缺失参数不能由模型补造。

已有成果与证据状态

已有音乐台及床铃场景作品可展示视觉方向；尚未将这些作品逐一绑定到本工作流的执行批次，不能把展示合集当成同次批量生成证明。

下方已有作品仅作成果选摘或表达参考，不能据此倒推生成工具、具体 Skill 版本或商业转化效果。

复用方式与适用边界

以新的产品资料重新确认事实与交付范围，复用策划方法、参考匹配和检查规则，不继承上一产品的尺寸、功能、认证、配件或销售承诺。已有规则不代表每种产品均已验证；未覆盖情况先做代表任务验证。
